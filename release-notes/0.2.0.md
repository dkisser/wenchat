# WenChat 0.2.0 — Application-layer reliability

WenChat 0.2.0 ships the Stage 1 application-layer reliability stack
(ADR 0001). Every outbound chat message now carries a per-peer monotonic
`seq` and is persisted to a JSONL outbox until the peer acknowledges
receipt, so reconnect and process restart no longer drop in-flight
messages or mid-transfer file chunks. LAN chat between two 0.2.0 builds
is a strict superset of LAN chat between two 0.1.x builds — the new
fields are additive and a pre-Stage-1 peer keeps working unmodified.

## Highlights for end users

- Chat messages and file transfers are no longer lost on reconnect or
  process restart. Unacknowledged messages resume from a persistent
  outbox; file transfers re-stream only the missing chunks.
- File transfers survive mid-transfer network drops — the receiver
  reports a bitmap of received chunks and the sender re-streams only
  what's missing, not the whole file.
- LAN chat between two 0.2.0 builds is wire-compatible with a 0.1.x
  build (additive `seq` field; legacy peers keep working).

## What's in here

### Features (protocol)

- per-peer monotonic `seq` on every control-plane message
- `message-ack` and `file-chunk-ack` frame types

### Features (core)

- `OutboxStore`: JSONL persistent queue, per-append fsync, soft
  tombstones, atomic compaction
- `MessageAckScheduler`: 200 ms idle / every-16 ACK cadence, 5-retry
  exponential backoff
- `ReceiveWindow` (LRU 256): dedup + gap detection
- `FileSender` / `FileReceiver`: chunk-level bitmap ACK + selective
  retransmit

### Fixed

- `sendFile` resolved in ~11 ms for 4 MiB files due to stale
  `bufferedAmount` capture
- `OutboxEntry` shape now derived from the Zod schema (`z.infer`)
  instead of a hand-written duplicate

### Docs / Project

- `CONTEXT.md` (project glossary)
